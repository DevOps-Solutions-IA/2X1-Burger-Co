# Runbooks operacionales

Estos procedimientos son seguros por defecto: diagnostican primero, no imprimen secretos y no autorizan cambios productivos sin owner gate. Cada incidente debe registrar release/buildId, requestId/traceId, tiempos, decisiones y evidencia sanitizada.

Runbooks: API, DB, restore, rollback, latencia, errores, stock, caja, WhatsApp, Sofia, backup, secretos y deployment.
